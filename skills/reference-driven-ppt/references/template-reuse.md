# 原生样板复用（T 类）

T 类案例含单页 PPTX 和 `object_map`，不是整套源文件；按需下载。它保留来源版式中的原生文字、图形、分组、连接线及独立图片，比按记忆画简图更能保留原案例的审美。N 类是更容易重组与换色的中性几何配方，两者不是质量等级。

1. `library.py fetch --cache <cache> --ids T01` 下载预览、单页样板及对象映射。查看实际图，再读 object_map；它只给出原生 shape_id 与原文，尚未替用户完成语义对应。
2. 建立 `content.json`：键为 `shape_<id>`，值为原生新文字。默认每个原生文字形状都要显式处理，包括旧标题、占位 X、年份、示例数值及页码；无需要保留的字段可设空字符串。用户事实来自当前材料。
3. `python <skill>/scripts/adapt_template.py --template <T01.pptx> --map <T01.json> --content <content.json> --out <project-build>/page-01.pptx`。脚本校验模板哈希，拒绝未知字段、漏字段和建议容量超限，不动图片、布局或源文件。保留首段样式作为新文案样式，富文本多种强调会统一为首个样式，需要在作者器内重新设置。`--allow-partial` 仅用于明确的局部编辑，不能用于隐藏残留示例文字。
4. 对新图表、表格、复杂内容与字体/颜色统一，用宿主 Presentations 的模板保留工作流编辑原生对象。若 API 导入丢失图形，不能把整页渲染图贴回去冒充复用；使用可保留版式的原生引擎，或转 N 类重建并披露差异。
5. Windows 有 PowerPoint 时，用 `scripts/merge_native_pages.ps1 -Manifest <manifest.json> -Output <deck.pptx>` 合并顺序指定的页面。插页后显式恢复源页面的 `Design`、`ColorScheme` 与背景继承，避免模板自动变成默认主题色。Manifest 为 `[{"path":"<absolute-page-path>","start":1,"end":1}]`。只创建新输出，不覆盖源文件、不关闭用户原有文档。画布不同则报错，不能直接拉伸。其他系统使用宿主的模板保留与原生合并功能并重新验证，或选 N 类作者器；此 Office 合并脚本不声称跨平台。合并后仍须实际打开并渲染检查。
6. 同一套汇报尽量选择同一风格的 T 类家族；跨家族先统一标题锚点、颜色、字体及视觉层次，不能直接拼成杂烩。配方的多样性不意味着字体与色彩可以各自为政。
7. 逐页渲染检查，测量实际换行和溢出。槽位容量只是一种预估，不能代替实际字号与字体检查。结构文字可编辑，照片与复杂插图仍为图片对象，交付时如实说明。

第三方源模板并非本技能原创；收录页供用户授权的设计参考与复用，保留已有署名，不给它们附加开源/商用授权。业务交付按所持权利使用。
