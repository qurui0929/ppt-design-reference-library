# 批量案例收录

本流程只在用户授权整理资源库时执行。

1. 明确来源目录和排除规则；原始文件保持原位，只读扫描。`scan_library.py --root <root> --out <private-index> --include <folder...>` 批量解析 PPTX ZIP/XML，增量缓存按相对路径、大小和修改时间判断。PPT、PDF、图片分别计数，不伪称已完成 PPTX 页面解析。
2. 分类来自目录、文本关键词和对象结构，初始状态为 `heuristic_unreviewed`。量化记录每页文字、原生图表/表格、图片、连接线、归一化几何。相同几何签名只作为候选去重，不能判定整页内容重复。
3. 优先从常用且构图明确的组件集抽样，导出逐页预览与总览，逐张查看拟收录页。记录实际预览路径和检查人。不要宣称全库都已审美评估。
4. 从案例提取信息结构和容量，编写中性原生配方。只引用构图，不复制原业务事实。原始模板、客户和个人内容不自动对外发布；公开资料也不能自动重新声明许可。
5. 发布区与本地索引分离。对外仅含精选、已审查的参考预览，匿名 source_ref、配方、SHA-256、review_status、version；本地绝对路径、姓名、私人备注、凭据和完整原始 PPT 不进入索引。第三方参考预览保持来源属性，不把它们改称原创或可任意商用。
6. 新增文件只写专用版本目录；保持原 GitHub 文件不动。通过 API 或 Git 提交前核对变更清单和大小，提交后重新读取远端清单/文件校验。凭据只从现有凭据管理器读取，不打印、不打包。
7. 用不同内容关系、正常与过载文案、不同配色及实际原生图表/表格测试；测试下载失败、哈希不符、缓存离线和槽位遗漏。发布包带测试报告的入口链接而不内置大图。

库中必须区分：自动分类、agent_reviewed、user_approved、原生示例渲染验收。维护者确认的案例不冒充最终用户审美批准。
